二、新发现（本轮换口径后浮出）

P1-4NEW高频输入框 14px → iOS 聚焦强制缩放视口
证据（代码级，客观判据）：style.css —— .fb-select / .fb-textarea / .fb-input: var(--fs-14)（反馈弹窗三件）、.dw-search input: var(--fs-14)（抽屉搜索，选卷选章的高频入口）；对照 .home-search input: var(--fs-16)——同一份 CSS 里规则共存，说明「≥16px 防 iOS 缩放」已知但未覆盖全。

机制：iOS Safari 聚焦 font-size <16px 的输入框时会自动放大视口（用户没法关），输入完弹回——每次搜索/反馈都被顶一下。
建议：移动端断点内 @media (max-width:900px){ .fb-select,.fb-textarea,.fb-input,.dw-search input{ font-size:16px; } }——桌面排版不动。工作量：0.25h。

P2-9NEWtheme-color meta 未随顶栏加深/主题切换更新
证据：index.html <meta name="theme-color" content="#667eea">——顶栏渐变 F3 已加深至 #5B67D4，iOS Safari 浏览器框染色比页面顶栏浅一档；暗夜主题下更明显。

JS 在主题/初始渲染时同步 meta[name=theme-color]（classic=#5B67D4，dark=暗夜顶栏值）。工作量：0.25h。

P2-10NEW桌面 crumb 停靠展开态 cursor:pointer 但点击 no-op
证据：app.js 6718「桌面=收起时展开停靠列（已展开 no-op）」；.crumb 无条件 cursor:pointer。

affordance honesty：≥1400 且停靠展开时 crumb 恢复 default cursor（或改为 title 提示「点 ☰ 收起」）。工作量：0.25h。
