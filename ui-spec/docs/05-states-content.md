# 05 · 状态覆盖与内容规范（States & Content）

> 专业设计系统与套版稿的最大分界：**是否渲染了全部五种状态**。每个取数/变换/接收数据的界面都必须有下表五态；只画"有数据的常态"是最常见的静默失败。

## 1. 五态定义与本应用实现

| 态 | 触发 | 必含要素 | 本应用实现 | 判定 |
|---|---|---|---|---|
| Loading | 数据在途 | 指示器 + 超时出口 | `loading-hint`（spinner+文案）；splash 启动进度条；音频「缓冲中…」 | ✓ |
| Empty | 无记录/无结果 | 标题 + 平实解释 + 主行动 | `empty-hint`（「本章还没有笔记」+引导）；搜索无结果计数 | ⚠ 空态建议统一带 CTA（见 §4） |
| Error | 请求失败/校验拒绝 | 原因 + 恢复动作 + 保留输入 | splash 错误+重试；音频「加载失败，请检查网络」+重试 | ✓（重试保留位置） |
| Populated | 常态 | 设计稿所画 | — | ✓ |
| Edge | 极端数据 | 布局不破 | 书名 shrink:99 不出半字碎屑；搜索结果>50 显式注明只显前 50；crumb 让位规则 | ✓ |

## 2. 各表面状态矩阵（核对单）

| 表面 | Loading | Empty | Error | Edge |
|---|---|---|---|---|
| 首页/合集层 | splash 进度 | 块网格恒有数据（不适用） | splash 错误+重试 | 长书名 |
| 读经/生命读经/书报/听抄 正文 | loading-hint | 章无内容→纲目回退自动识别 | loading-error+重试 | 长纲目行/超长节号 |
| 研读列（注解/纲目/笔记） | — | empty-hint「本章还没有笔记」 | —（本地数据） | 长笔记文本（textarea 可扩展） |
| 目录抽屉搜索 | — | 0 结果（计数=0 显式） | — | 结果>50 注明截断 |
| 听书播放 | 缓冲中… | 单分片讲次不渲染分段列表（合法空） | 加载失败+重试（保留位置） | 超长讲次名（crumb 收缩） |
| 笔记管理 | — | 分类无条目 | — | 200 字摘录截断 |
| 专题作业单 | — | 「待填」虚化行（不可点） | — | 条目全待填 |

**缺口**：正文 loading-error 重试目前无次数/退避策略（见 §6）；抽屉搜索 0 结果态建议回显查询词并给替代建议。

## 3. 加载阈值（按预期时长选指示器）

| 时长 | 指示器 |
|---|---|
| 0–300ms | 不显示（同步渲染） |
| 300ms–2s | 轻量 spinner |
| 2–10s | 贴布局的 skeleton 或带标签 spinner（「加载讲次…」） |
| 10–30s | 确定性进度条（splash 已具备） |
| 60s+ | 停止动画，给错误+重试/取消 |

规则：**每个请求都要起超时**；spinner 禁止无限转。splash 的「进度+失败重试」是正确示范。

## 4. 空态构成（空态是引导，不是空白）

- 首次空 = 标题 + 一句价值说明 + 主行动（如笔记空态：「写下你的第一个领受」+ 指向正文划线）。
- 无结果空 = **回显查询词** + 替代建议（"没有找到「xx」，试试书号或篇名"）。
- 清空空 = 可轻快一点；**错误永不伪装成空态**——错误有自己的态与恢复信息。

## 5. 错误三问与文案规范

每个错误按序回答：**发生了什么 → 原因（可知则给）→ 用户能做什么**。现状审读：

- 「音频加载失败，请检查网络」= 什么+原因 ✓，「重试」= 行动 ✓（范例级）。
- 禁止：「Something went wrong / 出错了」无原因无出口；错误文案不道歉、不含糊。

文案规则（全应用 UI 文案）：

1. 动词开头、具体优于聪明（「开始今天的读经」>「开始体验」）。
2. 同一动作全程同名：按钮「重试」→ 结果态仍叫「重试」，不换成「再试一次」。
3. 控件说清发生什么：「保存修改」而非「提交」。
4. 数字与时长用等宽（tabular-nums，播放器时间已遵守）。
5. 危险操作名称精确：删除就是「删除」，确认框明示条数与不可撤销（重读确认框已达标）。

## 6. 重试纪律

- 首次重试：用户点击立即执行。
- 第 2/3 次：指数退避 2s / 4s / 8s。
- 3 次失败后：「重试」换「联系支持」+ 可复制的错误标识（配合"复制带出处"既有能力）。
- 失败面显示「上次尝试：Xs 前」，让用户知道失败信息多旧。
- 现状：音频/splash 重试均立即执行、无退避——**建议作为 v1.1 改进项**。

## 7. Toast / 实时区域

- Toast `role="status"`（polite），出现位置全应用一致（底部居中 pill，已统一）。
- 自动消失的 Toast 必须可悬停/聚焦暂停（WCAG 2.2.1）——**现状未支持，改进项**。
- 实时区域容器必须先于内容存在于 DOM（动态插入 aria-live 不触发播报）。
- 致命错误用 `role="alertdialog"` 并移焦点；Toast 不移焦点。
