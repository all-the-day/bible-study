## 3. 抓取规程

### 3.1 URL 规律（ezoe.work，已实测）

```
书页   https://ezoe.work/books/{分类}/{书号}.html          列出「部/册/单元」链接
部页   https://ezoe.work/books/{分类}/{书号}-{部号}.html    列出该部下的「章」链接
章页   https://ezoe.work/books/{分类}/{书号}-{部号}-{章号}.html
       （无部分的书：{书号}-{单元}.html 即正文，如 2333-1.html）
```

分类号：福音 1 / 造就 2 / 教会与事奉 3 / 读经 4 / 传记文集 5 / 代售期刊 7 / 其他 8。
书页链接是**相对路径**（`href="2333-2.html"`），解析时拼绝对路径；`alt="上一页/下一页"` 的导航链接要排除。

### 3.2 两阶段抓取（省一半以上请求）

1. **阶段一（目录级）**：只抓 51 个书页 + 必要的部页，拿到全部章标题。
   与我们的库逐章比标题（用本工单第 1 节的同一套归一+匹配），列出「缺的章」。
   芫荽籽 CSV 的章标题可作交叉校验（两边标题不一致时以 ezoe.work 为准——我们最终引的是 ezoe 的正文）。
2. **阶段二（正文级）**：只抓缺的章。预计 ~950 个请求，`sleep 1` 约 16 分钟。

### 3.3 网络与校验

- 直连 `ezoe.work` 当前不通（curl 超时）；走代理 `http://127.0.0.1:7897` 正常（2026-11-02 实测）。
  2026-10-13 时是反的（直连可用、代理失效）——**两种都试，别写死**。
- 源站无防护：无 User-Agent/Referer 校验（芫荽籽 APK 的获取器就是无头发 GET，见其分析报告 §6.1）。
- 每本书抓完对照芫荽籽基线章数；对不上就停，别硬跑。
- 正文清洗沿用 `read_ezoe_md`（剥二行式书名篇名头、剥 markdown 记号、剥尾部来源元数据），**不要新写清洗规则**。

## 4. 落库红线（索引稳定）

标注按 `(series, volume, book, chapter)` + 章内偏移定位。**任何插入/重排/删除都会让旧标注错位丢失**。

1. **只追加，不插入**：新书追加到目标系列该卷 `books` 末尾；补章追加到该书 `chapters` 末尾。
   既有条目序号、顺序、内容一律不动。
2. **不重导既有系列**：gospel/zj/jh/reading/periodicals/misc/bio 保持冻结产物不动，补抓内容作为增量进入
   （gospel 冻结先例：AGENTS.md 已记录「重导会让索引位移、旧标注错位」，本工单不重复这个错误）。
3. **「补章」默认补成新书，不并进现有书**：如 `4063 新约总论` 补 204 章 → 在 reading 末尾新增一本书，
   而不是塞进 xyzl 的八册。塞现有书哪怕是末尾追加，也会让该书章数变化、与 sg/zj 侧的重复关系更乱。
   （若某本书经人工核确认「同一本书的残缺版」，才走末尾追加补章，且只追加缺的章。）
4. **重复篇照旧墓碑化**：补进来的章若与既有内容重复（相似度 ≥0.98），正文换墓碑指引，条目保留。
5. **部折叠规则与现 export 一致**：多「部」书按索引 `part` 折叠成「书名·部」。
6. 不动 `data/books/numbers.json` 的既有条目；新书若带 ezoe 书号（1001–8999 段）一并登记，
   便于书号检索（gaps §3.3 的「已合并未挂书号」问题会顺带缓解）。
